# Best Buy 降价雷达 · 电脑

盯 Best Buy 的笔电和台式机降价。开着就行，它按设定的间隔自动查，
把每台机器拆成 `cpu / gpu / ram / disk / 屏幕` 一行一行列出来，
价格写成 `原价 → 现价`，降价的机器进历史记录并弹 Windows 通知。

覆盖全新、**官翻 (Refurbished)**、二手 (Pre-Owned) 和 **Open Box 拆封**。

```
sku      name                cpu           gpu       ram             disk  screen           price               off
6613961  ROG Zephyrus G16    u9 285H       5070      16G LPDDR5X     1T    16" OLED 240Hz   1799.99             —
6672161  Yoga Slim 7x        SDX Elite     核显       16G             512G  14" OLED         1299.99 → 749.99    -42%
10551252 Victus 2023         r7 7445HS     4050      16G             512G  15.6" 144Hz      1474.99 → 939.00    -36%
```

**不需要注册、不需要 API Key，装好就能跑。**

## 跑起来

需要 Node.js 18+ 和一个 Chromium 内核浏览器（Windows 11 自带的 Edge 就行）。

**双击 `start.cmd`**，或者：

```bash
npm start
```

浏览器会自动打开 `http://127.0.0.1:8787`。点右上角「立即查询」跑第一轮，
大约 3 分钟，之后每 30 分钟自动跑一次。关掉那个黑窗口就等于退出软件。

零 npm 依赖 —— 不用 `npm install`，直接跑。

## 打包给别的电脑用

```bash
npm run build
```

产出 `dist/BestBuy-Price-Tracker-v1.0.0-win-x64.zip`（约 33 MB，解压后 88 MB）。
拷到目标机器 → 解压 → 双击「启动.cmd」。**不用装 Node、不用管理员权限、不用注册账号。**

目标机器只需要：Windows 10/11 64 位 + 有 Edge 或 Chrome（Win10/11 自带 Edge）。

**为什么是「带 node.exe 的文件夹」而不是单个 exe**
本项目是 ESM 多模块 + `import.meta.url`，而 Node 内置的 SEA 只吃单文件 CJS ——
得先用打包器转成 CJS，动态 import、`import.meta`、`__dirname` 的语义都会变，
多一层转换就多一层出错的地方。带一个官方 `node.exe` 最省事也最稳，代价只是体积。
`pkg` 已停止维护且不支持新版 Node，直接排除。

打包脚本会做这些事：

- **不打包 `data/`** —— 那是用户数据，里面可能存着 API Key
- **真跑一遍冒烟测试** —— 用打进包里的 `node.exe` 把服务完整启动，
  验证首页、电脑榜接口、历史记录接口、优雅关机全通，再关掉。
  这一步过了基本就等于在目标机器上能跑
- 测试用独立的临时数据目录，测完清干净，保证发出去的包不含任何用户数据
- 批处理内容全部是 ASCII（cmd.exe 按 OEM 代码页解析 `.cmd`，中文字节会打乱块结构）

便携版的数据就放在自己文件夹的 `data/` 里，整个文件夹拷走，历史记录跟着走。
要是解压到了 Program Files 这类写不进去的地方，会自动退到
`%LOCALAPPDATA%\BestBuyTracker\data`，启动日志里会写明。

**同一台机器上跑多份拷贝**：两份都默认用 8787，会撞。`bbt` 靠安装目录分辨
"端口上答话的是不是我这份"，所以在 A 目录敲 `bbt stop` 不会把 B 目录那份停掉，
只会提示你去哪个文件夹操作、或者 `bbt port 8788` 给本份换个端口。

## 起停和换端口：`bbt`

`start.cmd` 是「开个窗口看着它跑」。想让它在后台待着、或者要换端口，用控制程序：

```bash
bbt                # 交互菜单（双击 bbt.cmd 也是进这个）
bbt status         # 看状态：端口、PID、运行多久、定时器开没开
bbt start          # 后台启动
bbt start 9000     # 用 9000 启动，并把它记成默认端口
bbt stop           # 停止
bbt restart        # 重启
bbt port 9000      # 改默认端口；正在跑的话顺手重启
bbt open           # 浏览器打开界面（没在跑就先拉起来）
```

从 PowerShell 里就写 `.\bbt.cmd status`。`npm run stop` / `npm run restart` 也通。

几个特意做的处理：

- **认进程不靠杀 node.exe。** 服务启动时在 `data/server.pid` 里记下 pid、端口和一个随机 token，
  控制程序据此确认「这个进程确实是我」。这台机器上跑着别的 node 程序也不会被误伤。
- **停止是优雅的。** 走 HTTP 关机接口，让服务先停调度、把价格数据落盘再退出，
  所以会看到「已停止（数据已保存）」。只有它卡住不响应时才升级到强杀。
  那个接口要带 token，浏览器里的网页就算猜到端口也关不掉它。
- **端口写进配置文件，不用环境变量。** shell 里残留一个 `PORT` 会静默劫持端口 ——
  这坑踩过，所以 `bbt start` 会显式把 `PORT` 从子进程环境里删掉。
- **端口被占会说清楚**，并告诉你 `netstat -ano | findstr :端口` 去查是谁占的。
- **陈旧 pid 文件能自愈**：进程被任务管理器强杀后，`bbt status` 会识别出来并清理。
- `start.cmd` 和 `bbt` 互通：前台窗口起的服务，照样能被 `bbt stop` 优雅停掉。

`bbt status` 在未运行时返回退出码 1，方便写脚本判断。

## 数据是怎么来的

默认通道叫 **web**：用你本机的 Edge/Chrome 开一个后台实例，去读 Best Buy
自己的搜索结果页，从商品卡里提取型号、价格、原价、品相。因为是真浏览器，
页面能正常渲染，不会像裸 HTTP 请求那样被挡在挑战页外面。

规矩（写死在代码里）：

- 请求之间强制间隔 2.5 秒，一轮最多翻两页，不并发
- 只读公开的商品价格，不登录、不下单、不碰账号
- **遇到验证码或封禁页立刻停手并如实报错，不做任何绕过尝试**

### 已知边界

在摸清 Best Buy 现在的反爬策略后，实测结论：

| | 状态 |
|---|---|
| 搜索结果页 | ✅ 正常，这是数据主来源 |
| 商品详情页 | ❌ 被拒（返回连接错误），**取不到** |
| 按 SKU 精确搜索 | ❌ 会被重定向到详情页，等于取不到 |

由此带来两个实际影响：

1. **没有「重量」列**。重量只在详情页的规格表里，搜索卡片没有。
   屏幕尺寸、CPU、显卡、内存、硬盘都能从商品名解析出来，唯独重量不行。
2. **关注列表靠型号名反查**。刷新某台机器的价格时，软件拿它的品牌+型号去搜，
   再从结果里按 SKU 认领。同型号变体太多时偶尔会认领不到，
   这一轮就跳过不更新（保留上次价格，不会写入猜的数字），列表里会标一个 `!`。

想要完整字段（含重量）就得用官方 API —— 见下。

### 另一条通道：官方 API

`developer.bestbuy.com` 的开放平台字段最全、限速明确、最稳。
但**注册账号要求填美国手机号**（`Mobile Phone Number` 是必填项），
没有美区号码就走不通。有 Key 的话在「设置 → 数据源」里填进去，
通道切成 `官方 API` 或 `有 Key 走 API，否则回落浏览器`。

## 界面

| 页面 | 干什么 |
|---|---|
| **电脑榜** | 所有查到的机器，一行一台，可按价格 / 折扣 / 显卡 / 内存排序。点 ☆ 加入关注 |
| **历史记录** | 每一次降价、新发现、涨价、补货都在这。可按类型和时间筛，能导出 CSV |
| **关注** | 单独盯住的机器，保留完整价格曲线和历史最低价，可以设目标价 |
| **自动搜索** | 定时查询要跑哪些条件。默认 5 条（游戏本 / 笔记本 / 台式 / 官翻 / Open Box） |
| **设置** | 通道、间隔、降价阈值、通知、免打扰、日志 |

绿色左边框 = 24 小时内降过价。`新低` = 跟踪三轮以上并且跌破了此前最低点。
`三方` = Best Buy Marketplace 第三方卖家（SKU 8 位），退换货政策和自营不同，
可以在设置里一键隐藏。

## 降价是怎么算出来的

**不是**看 Best Buy 页面上那个「原价 → 现价」标签，而是软件自己记的。

每台机器进榜后，每轮都记一次价格。这一轮比上一轮低，就是一次降价，
写进历史记录并通知。所以那些一直挂着原价、某天悄悄降了的机器也跑不掉 ——
这也是为什么默认的自动搜索**故意不加**「只要正在打折的」这个条件：
先把机器收进来持续跟踪，让时间去发现降价。

**降价阈值**（设置里）：低于阈值的小幅波动照样更新价格，但不写历史记录、不弹通知。
盯很多机器的时候把它调到 3% 或 $20，世界会清静很多。

每一轮的流程：

1. 刷新关注列表 —— 逐台反查价格，记一个采样点用于画曲线
2. 跑每条启用的自动搜索 —— 命中的机器写进电脑榜
3. 通知 —— 降价的弹 Windows 桌面通知（免打扰时段内只记录不弹）
4. 清理 —— 删过期采样点，把 45 天没再出现的机型移出榜单

间隔默认 30 分钟，带 ±12% 随机抖动。上一轮没跑完就跳过这一轮，不会堆积。

## 文件

```
start.cmd                 双击启动（前台窗口）
bbt.cmd                   控制程序：起停 / 换端口 / 菜单
server.js                 HTTP 服务 + API 路由
scripts/ctl.js            bbt 的实现
src/
  config.js               默认设置、种子搜索
  instance.js             pid 文件 + 实例 token
  store.js                JSON 持久化（原子写 + JSONL 追加）
  tracker.js              调度器、降价判定、事件生成
  specs.js                规格解析：商品名 → cpu/gpu/ram/disk/screen
  notify.js               Windows 桌面通知（WinRT toast）
  util.js                 HTTP、限速、日志
  browser/cdp.js          零依赖的 Chrome DevTools Protocol 驱动
  providers/
    bestbuyWeb.js         网页通道（默认）
    bestbuyApi.js         官方 API 通道
    scrape.js             裸 HTTP 抓取（基本必被拦，保留作对照）
public/                   前端（原生 JS，无构建步骤）
data/                     运行时生成，全部数据都在这
scripts/demo-seed.js      演示数据
```

`browser/cdp.js` 是用 Node 24 自带的全局 `WebSocket` 直接跟浏览器的
DevTools 协议对话的，所以不需要 Playwright/Puppeteer，也不用下 300MB 的浏览器。

`data/` 里：`settings.json`、`watchlist.json`、`searches.json`、
`board.json`（电脑榜快照）、`events.jsonl`（历史记录）、`observations.jsonl`（价格采样）。
直接复制这个目录就能搬到另一台机器。

## 常见问题

**第一轮很慢** —— 要开浏览器、翻 10 个页面，3 分钟左右正常。之后是后台自动跑，
不占用你。

**一台机器都没查到** —— 设置页点「测浏览器」看具体报错。如果提示被验证码挡了，
把「浏览器无头运行」关掉改用真实窗口（会移到屏幕外，你看不见），通常能过。

**端口被占用** —— `bbt port 9000` 换一个。想知道是谁占着：`netstat -ano | findstr :8787`。

**通知不弹** —— Windows 设置 → 系统 → 通知，确认没开专注助手。设置页点「测通知」验证。

**折扣百分比和商品页对不上** —— 榜里的折扣按「原价 vs 现价」现算。Best Buy 页面上
有时叠加了会员价、以旧换新、捆绑优惠，这些拿不到。以商品页为准。

**想先看看界面** ——

```bash
node scripts/demo-seed.js
```

灌一批**编造的**演示数据（价格是假的，别拿去下单）。看完 `node scripts/demo-seed.js --clear` 清掉。
