# Best Buy 降价雷达

盯 **Best Buy / B&H / Amazon** 上的电脑和装机配件降价的小工具：

- **电脑**：笔电、台式、一体机，覆盖全新、**官翻 (Refurbished)**、二手 (Pre-Owned) 和 **Open Box 拆封**
- **配件**：显卡、CPU、内存、固态硬盘

开着就行，它按设定的间隔自动查，把每台机器拆成 `cpu / gpu / ram / disk / 屏幕`
一行一行列出来。它不只告诉你「降价了」，还会判断**现在这个价到底值不值**：
同配置的别家卖多少、这台自己过去是什么价位。降价写进历史记录，弹 Windows 通知，也可以推到手机。

```
sku      name                cpu           gpu       ram             disk  screen           price               off
6613961  ROG Zephyrus G16    u9 285H       5070      16G LPDDR5X     1T    16" OLED 240Hz   1799.99             —
6672161  Yoga Slim 7x        SDX Elite     核显       16G             512G  14" OLED         1299.99 → 749.99    -42%
10551252 Victus 2023         r7 7445HS     4050      16G             512G  15.6" 144Hz      1474.99 → 939.00    -36%
```

**不需要注册、不需要 API Key，零 npm 依赖，装好 Node 就能跑。** 只支持 Windows。

> 个人自用的捡漏工具，灵感来自 B 站「北美垃圾佬」。
> 本项目与 Best Buy、B&H Photo、Amazon 均无任何关联。

## 跑起来

需要：

- Windows 10 / 11
- **Node.js 22 或更新**（要用 Node 自带的全局 `WebSocket`；开发用的是 Node 24）
- 一个 Chromium 内核浏览器 —— Windows 自带的 Edge 就行，没有的话装 Chrome

**双击 `start.cmd`**，或者：

```bash
npm start
```

浏览器会自动打开 `http://127.0.0.1:8787`。启动后会先跑一轮，之后每 30 分钟自动跑一次。
第一轮要开浏览器挨个翻页（默认 23 条搜索、三家零售商），需要好几分钟，之后都在后台跑，不占用你。
关掉那个黑窗口就等于退出软件。

不用 `npm install` —— 没有任何依赖。

## 界面

| 页面 | 干什么 |
|---|---|
| **电脑榜** | 所有查到的机器，一行一台。可按「值不值」、历史低位、同档最便宜、价格、显卡、内存等排序，可只看降价 / 有货 / 真好价。点 ☆ 加入关注 |
| **硬件** | 显卡、CPU、内存、固态，按芯片 / 显存 / 容量对比。同一件东西在三家的价格放在一起看 |
| **历史记录** | 每一次降价、新发现、涨价、补货都在这。可按类型、时间范围筛，按跌幅、挂价时长等排序，能导出 CSV |
| **关注** | 单独盯住的机器，保留完整价格曲线和历史最低价，可以设目标价 |
| **自动搜索** | 每轮要跑哪些查询。默认 23 条，覆盖三家的笔电 / 台式 / 官翻 / Open Box / 四类配件，外加一个具体型号（幻14）的示例 |
| **设置** | 数据源、间隔、降价阈值、通知、免打扰、手机推送、特别关注、诊断 |

榜上的标记：

- 绿色左边框 = 24 小时内降过价
- `新低` = 跟踪三轮以上，并且跌破了此前的最低点
- `缺货` = 售罄，整行变暗、价格划线（默认不隐藏，勾「只看有货」可以藏起来）
- `三方` = Best Buy Marketplace 第三方卖家（SKU 8 位），退换货政策和自营不同，可以在设置里一键隐藏
- 「商家」列只在榜上有不止一家零售商时出现

## 值不值怎么判断

**不看**页面上的折扣百分比 —— 零售商的「原价」常年虚高，-40% 可能只是虚标。
而是用两把尺子，**都会明确告诉你数据够不够**，宁可显示「数据不足」，也不给没有统计意义的数字。

1. **同档横向分位**：同配置的机器现在都卖多少，这台排第几。
   - 电脑按四级阶梯找「同档」：`形态+显卡+内存+硬盘` → `形态+显卡+内存` → `形态+显卡+CPU 档` → `形态+显卡`，
     取样本 ≥ 5 台的最细一层，并把用的是哪一层显示出来
   - 配件是精确同款对比（比如同一颗芯片 + 同样显存），样本 ≥ 3 就算数
   - 跨零售商一起比：同一张卡在 Best Buy、B&H、Amazon 各卖多少，一眼可见
2. **自身历史分位**：当前价在它自己过去 90 天价格分布里的位置，**按时间加权**
   （不按采样点数加权 —— 采样密度随查询频率变）。至少跟踪 3 天且价格真的变过才给出。

**评分** = 两把尺子的加权（历史 60%、同档 40%）。只有一边有数据的，分数压到 **70 封顶**，
免得「同档没样本、只是自己历史上便宜」的机器排到证据完整的真好价前面。

**真好价** = 历史分位 ≤ 15% **且** 同档分位 ≤ 35%。阈值在 `data/settings.json` 里能改
（`trueDealHistPct` / `trueDealCrossPct`）。

刚开始用的时候「历史」一列基本都是「—」：价格轨迹要攒几天、而且价格得真的动过才有意义。
这是数据还不够，不是坏了。

## 降价是怎么算出来的

**不是**看页面上那个「原价 → 现价」标签，而是软件自己记的。

每台机器进榜后，每轮都记一次价格，**价格变了才追加一条**。这一轮比上一轮低，就是一次降价，
写进历史记录并通知。所以那些一直挂着原价、某天悄悄降了的机器也跑不掉 ——
这也是为什么默认的自动搜索**故意不加**「只要正在打折的」这个条件：
先把机器收进来持续跟踪，让时间去发现降价。

**降价阈值**（设置里）：低于阈值的小幅波动照样更新价格，但不写历史记录、不弹通知。
盯很多机器的时候把它调到 3% 或 $20，世界会清静很多。

每一轮的流程：

1. 刷新关注列表 —— 逐台反查价格，记一个采样点用于画曲线
2. 跑每条启用的自动搜索 —— 命中的机器写进电脑榜 / 硬件榜
3. 通知 —— 降价的弹 Windows 桌面通知、按设置推到手机（免打扰时段内只记录不弹）
4. 清理 —— 删过期采样点，把 45 天没再出现的商品移出榜单

间隔默认 30 分钟，带 ±12% 随机抖动。上一轮没跑完就跳过这一轮，不会堆积。

### 特别关注

盯住某个品牌或某台机器（比如「幻14」「5070 ti」），它大降价时第一时间通知。
每条规则可以设：关键词（空格分隔 = 全部命中）、限定哪家零售商、降幅至少多少 % / 多少美元、价格上限、
免打扰时段是否也提醒。

命中的规则**绕开全局降价阈值**，也不受「每轮最多通知几条」的限制，通知单独成条。
全局阈值是「降这么多才值得打扰我」，特别关注是「这台我盯着，标准另算」—— 两者方向相反，所以分开。

### 手机推送

人不在电脑前也能收到。支持两种，都不用注册：

- **ntfy**（iOS / Android）：装 App，订阅一个主题名。**主题名就是密码**，设置页可以一键生成随机长串
- **Bark**（仅 iOS）：填 App 里的设备 Key

默认只推特别关注的命中；关掉「只推特别关注」后，普通降价也推，但每轮限量。设置页点「测手机」验证。

## 数据是怎么来的

默认通道叫 **web**：用你本机的 Edge/Chrome 开一个后台无头实例，去读零售商**公开的搜索 / 分类结果页**，
从商品卡里提取型号、价格、原价、品相、是否有货。因为是真浏览器，页面能正常渲染。

规矩（写死在代码里）：

- 翻页之间至少间隔 2.5 秒，不并发；每条搜索默认翻 2 页
- 只读公开的商品价格，不登录、不下单、不碰账号
- **遇到验证码或拦截页立刻停手并如实报错，不做任何绕过尝试**。
  某家本轮被拦了，这一轮就跳过它剩下的搜索，下一轮再试

使用前请自行确认你的用法符合各网站的使用条款。价格以商品页为准。

### 各家的情况

| 零售商 | 怎么查 | 备注 |
|---|---|---|
| **Best Buy** | 搜索结果页 | 数据主来源。商品详情页取不到（被拒），按 SKU 精确搜索会被重定向到详情页，同样取不到 |
| **B&H** | 分类页 | 关键词搜索页结构不同、提取不到，所以只走分类页。偶尔会挡（显示「请稍候」），挡了就本轮跳过 |
| **Amazon** | 关键词搜索 | 商品最全，但同款重复和第三方 listing 也最多 |
| Micro Center | 不支持 | 搜索页有 Cloudflare 人机验证，按上面的规矩不碰 |

由此带来的实际影响：

1. **「重量」列基本是空的**。重量只在详情页的规格表里，搜索卡片上没有。
   屏幕、CPU、显卡、内存、硬盘都能从商品名解析出来，唯独重量不行
2. **关注列表靠型号名反查**。刷新某台机器的价格时，软件拿它的品牌 + 型号去搜，
   再从结果里按 SKU 认领。同型号变体太多时偶尔会认领不到，
   这一轮就跳过不更新（保留上次价格，不会写入猜的数字），列表里会标一个 `!`

### 另一条通道：Best Buy 官方 API

`developer.bestbuy.com` 的开放平台字段最全（含重量）、限速明确、最稳。
但**注册账号要求填美国手机号**，没有美区号码就走不通 —— 所以本项目的所有功能都不依赖它。
有 Key 的话在「设置 → 数据源」里填进去，通道切成 `官方 API` 或 `有 Key 走 API，否则回落浏览器`。

## 打包给别的电脑用

```bash
npm run build
```

产出 `dist/BestBuy-Price-Tracker-v1.0.0-win-x64.zip`（约 33 MB，解压后 88 MB）。
拷到目标机器 → 解压 → 双击「启动.cmd」。**不用装 Node、不用管理员权限、不用注册账号。**

目标机器只需要：Windows 10/11 64 位 + 有 Edge 或 Chrome（Win10/11 自带 Edge）。

**为什么是「带 node.exe 的文件夹」而不是单个 exe**
本项目是 ESM 多模块 + `import.meta.url`，而 Node 内置的 SEA 只吃单文件 CJS ——
得先用打包器转成 CJS，动态 import、`import.meta`、`__dirname` 的语义都会变，
多一层转换就多一层出错的地方。带一个官方 `node.exe` 最省事也最稳，代价只是体积。
`pkg` 已停止维护且不支持新版 Node，直接排除。

打包脚本会做这些事：

- **不打包 `data/`** —— 那是用户数据，里面可能存着 API Key 和推送主题
- **真跑一遍冒烟测试** —— 用打进包里的 `node.exe` 把服务完整启动，
  验证首页、电脑榜接口、历史记录接口、优雅关机全通，再关掉。
  这一步过了基本就等于在目标机器上能跑
- 测试用独立的临时数据目录，测完清干净，保证发出去的包不含任何用户数据
- 批处理内容全部是 ASCII（cmd.exe 按 OEM 代码页解析 `.cmd`，中文字节会打乱块结构）

便携版的数据就放在自己文件夹的 `data/` 里，整个文件夹拷走，历史记录跟着走。
要是解压到了 Program Files 这类写不进去的地方，会自动退到
`%LOCALAPPDATA%\BestBuyTracker\data`，启动日志里会写明。

**同一台机器上跑多份拷贝**：两份都默认用 8787，会撞。`bbt` 靠安装目录分辨
"端口上答话的是不是我这份"，所以在 A 目录敲 `bbt stop` 不会把 B 目录那份停掉，
只会提示你去哪个文件夹操作、或者 `bbt port 8788` 给本份换个端口。

## 起停和换端口：`bbt`

`start.cmd` 是「开个窗口看着它跑」。想让它在后台待着、或者要换端口，用控制程序：

```bash
bbt                # 交互菜单（双击 bbt.cmd 也是进这个）
bbt status         # 看状态：端口、PID、运行多久、定时器开没开
bbt start          # 后台启动（运行日志写到 data/server.log）
bbt start 9000     # 用 9000 启动，并把它记成默认端口
bbt stop           # 停止
bbt restart        # 重启
bbt port 9000      # 改默认端口；正在跑的话顺手重启
bbt open           # 浏览器打开界面（没在跑就先拉起来）
```

从 PowerShell 里就写 `.\bbt.cmd status`。`npm run stop` / `npm run restart` 也通。

几个特意做的处理：

- **认进程不靠杀 node.exe。** 服务启动时在 `data/server.pid` 里记下 pid、端口和一个随机 token，
  控制程序据此确认「这个进程确实是我」。这台机器上跑着别的 node 程序也不会被误伤。
- **停止是优雅的。** 走 HTTP 关机接口，让服务先停调度、把价格数据落盘再退出，
  所以会看到「已停止（数据已保存）」。只有它卡住不响应时才升级到强杀。
  那个接口要带 token，浏览器里的网页就算猜到端口也关不掉它。
- **端口写进配置文件，不用环境变量。** shell 里残留一个 `PORT` 会静默劫持端口 ——
  这坑踩过，所以 `bbt start` 会显式把 `PORT` 从子进程环境里删掉。
- **端口被占会说清楚**，并告诉你 `netstat -ano | findstr :端口` 去查是谁占的。
- **陈旧 pid 文件能自愈**：进程被任务管理器强杀后，`bbt status` 会识别出来并清理。
- `start.cmd` 和 `bbt` 互通：前台窗口起的服务，照样能被 `bbt stop` 优雅停掉。

`bbt status` 在未运行时返回退出码 1，方便写脚本判断。

## 常见问题

**第一轮很慢** —— 要开浏览器、三家零售商挨个翻页，几分钟正常。之后是后台自动跑，不占用你。

**一台机器都没查到** —— 设置页点「测浏览器」看具体报错，`data/server.log` 里也有每一页抓到多少。
如果是被验证码或拦截页挡了，软件会停手报错，不会尝试绕过；过一阵再试，或者把查询间隔调长。

**榜上的机器比网页上少** —— 默认无头运行（不开窗口），实测在 Best Buy 上无头模式每页拿到的商品
大约只有窗口模式的一半。想抓得全一点，可以在设置里关掉「浏览器无头运行」，
代价是会真的开一个窗口（会被移到屏幕外）。

**端口被占用** —— `bbt port 9000` 换一个。想知道是谁占着：`netstat -ano | findstr :8787`。

**通知不弹** —— Windows 设置 → 系统 → 通知，确认没开专注助手。设置页点「测通知」验证。

**折扣百分比和商品页对不上** —— 榜里的折扣按「原价 vs 现价」现算。零售商页面上
有时叠加了会员价、以旧换新、捆绑优惠，这些拿不到。以商品页为准。

**想先看看界面** ——

```bash
node scripts/demo-seed.js
```

灌一批**编造的**演示数据（价格是假的，别拿去下单）。看完 `node scripts/demo-seed.js --clear` 清掉。
